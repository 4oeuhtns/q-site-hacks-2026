# Setup

Everything needed to work on this repo, written against what is actually
installed here rather than copied from the notebook.

---

## 1. Prerequisites

- **macOS or Linux.** The notebook states Windows users should work under WSL2:
  archive extraction and the local smoke worker use POSIX facilities.
- **Python 3.12 or 3.13.** These match the documented submission runtime.
  This machine runs **3.12.14**.
- Git, and about 1 GB of disk for the environment.

## 2. Environment

This repo currently uses a **conda** environment named `q-site-hacks-2026`
(`/opt/miniconda3/envs/q-site-hacks-2026`), not the venv the notebook suggests.
Either works; use whichever you already have.

### Known version drift

| package | notebook pin | installed here |
|---|---|---|
| numpy | 2.3.5 | 2.3.5 |
| scipy | **1.17.0** | **1.18.1** |
| pydantic | 2.13.4 | 2.13.4 |
| httpx | 0.28.1 | 0.28.1 |
| numba | 0.65.1 | 0.65.1 |
| llvmlite | 0.47.0 | 0.47.0 |

SciPy is one minor version ahead of the pin. Everything runs, but the optimiser
paths (`scipy.optimize.minimize`, L-BFGS-B) are load-bearing for every learner in
this project, so local recovery numbers are not guaranteed to match the graded
runtime exactly. Pin it to 1.17.0 if you need to reproduce a graded result
precisely.

`numba` and `llvmlite` are only needed by the eight-qubit learner. Cup 1 work
does not touch them, but `duelkit.recovery8.quantum` imports `njit` at module
load, so they must be installed for any import that reaches `recovery8`.

## 3. Generate the SDK

`ionq/_quantum_duel_sdk_0_7_2/` is **generated, not committed**. It is written by
the large folded Setup cell inside the notebook (cell 8, ~168 KB of embedded
source with content hashes).

```bash
jupyter lab                       # open ionq/Quantum_Duel_Student.ipynb
```

Select the kernel from step 2, then run every cell in **Setup** through
**Drawing circuits**. That writes `_quantum_duel_sdk_0_7_2/` next to the
notebook.

The setup cell **will not overwrite** SDK files you have edited. If you have
modified them and want a clean copy, move the directory aside and re-run.

## 5. Day-to-day commands

Run from `ionq/`.

```bash
# score the stock SDK learner against the public bank
python3 dev/harness.py

# score your defender, on chosen draw seeds
python3 dev/harness.py --defender quantum_duel_work/quantum-duel-4q-playtest-0.3/my_solution/main.py \
                       --seeds 41 73 907

# one attack family only
python3 dev/harness.py --attack 4q_ladder --seeds 41

# reproduce a measurement from findings.md
PYTHONPATH=dev/experiments python3 -u dev/experiments/crb.py
```

`harness.py` captures defender exceptions rather than raising, so a crashing
defender shows as `FAILED` with its error instead of killing the run.

### Reproducibility

Pin threads before any timing comparison. The official smoke worker sets these,
and BLAS threading otherwise makes runtimes incomparable between machines:

```bash
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
```

Draw seeds are the opponent. A template plus a seed is one concrete attack, so
always compare defender revisions on the **same** seeds and keep a few fresh ones
in reserve for a final check.

## 6. Building a submission

Done through the notebook's Part 4 cells, which call `build_submission` and
`validate_solution` from `qduel_sdk.submission`. The packager takes an explicit
allowlist of source files — a helper you forget to list fails in the smoke test,
not at the tournament.

```
quantum_duel_work/quantum-duel-4q-playtest-0.3/submission.zip
```

The archive contains `main.py`, `attacks.json`, `qduel.json` and
`submission.json`. Upload **the ZIP**, never the notebook or the workspace.

`VALIDATED_LOCALLY` means the archive passed local checks and the smoke cases
executed. It is not a claim about recovery quality — a valid program can score
zero.

## 7. Troubleshooting

Real failures hit while working in this repo:

| Symptom | Cause and fix |
|---|---|
| `command not found: timeout` | macOS has neither `timeout` nor `gtimeout`. `brew install coreutils` for `gtimeout`, or just drop it. |
| `ValueError: Request crosses checkpoint; close it explicitly first` | A block is exactly `total_shots / checkpoints` (4,000 for Cup 1). You cannot query past it — call `close_checkpoint()` between blocks. |
| `Distinct-setting budget exhausted` | 180 settings for the **whole** encounter, and changing the analysis circuit makes a new setting. Re-querying an existing setting is free. |
| `Encounter action limit reached` | 600 actions total. The stock learner already uses 546; a batch of 32 queries costs 32 actions, not 1. |
| `ModuleNotFoundError: qiskit` in a smoke test | The runner image has only stdlib, the SDK, NumPy/SciPy, Numba/llvmlite, Pydantic and HTTPX. Remove framework imports from `main.py`. |
| Background script prints nothing until it exits | Python buffers when piped. Use `python3 -u`, and avoid `\| tail` if you want progress. |
| A `pgrep -f "foo.py"` wait loop never finishes | The waiting shell's own command line contains `foo.py`, so `pgrep` matches itself. Match on the interpreter, or use a marker file. |
| Different SDK already imported | Restart the kernel and re-run the Setup cell. Do not mix release directories. |
